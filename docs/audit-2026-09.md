## 3. Security

### Strengths

- **Contact request guard** (`src/lib/contact-request-guard.ts`). Requests must pass an Origin allowlist, then a custom `x-contact-session` header (which forces a CORS preflight), then a Vercel Firewall rate limit per IP and per session, then BotID. The guard fails closed with a 503, and bodies are read as a capped stream before parsing.
- **Strict validation.** zod schemas are `.strict()` throughout, and `briefLink` must be https with no credentials.
- **AI output is only a proposal.** The model has no tools. Its reply is validated against a strict schema and the visitor reviews it. The model can't choose recipients or produce HTML, and validation logs never contain visitor text.
- **Email.** The main enquiry only ever goes to `CONTACT_DELIVERY_TO`, so there is no open relay. Resend is called through its JSON API, CR/LF is collapsed, values are HTML-escaped, and an Idempotency-Key is sent.
- **Uploads.**
  - Magic bytes are sniffed, and the extension and declared type must match the contents.
  - Filenames are allowlisted.
  - Files go to private Blob storage with a random suffix.
  - An upload is rejected if its cleanup can't be scheduled.
  - Downloads are sent with `attachment`, `nosniff` and `no-store`.
- **Capabilities.** They are HMAC-SHA256 with `timingSafeEqual`, have an expiry, and the review and attachment schemas can't be swapped for each other. Each is single use because the hook is disposed after the decision. The review page is `noindex` with `no-referrer`.
- **Rendering.** JSON-LD escapes `<`, `react-markdown` runs without raw HTML, rich-block URL and ID schemas are regex-checked, and `ExternalLink` sets `rel="noopener noreferrer"`.
- **Secrets.** No secrets appear in tracked files or git history, and `.env*` is gitignored.

## 4. Performance

### Strengths

- **Static generation.** 107 routes are prerendered, including all writing pages (`dynamicParams = false`), `llms.txt`, `design.md`, `.well-known/*`, the sitemap and robots.
- **OG images.** They are generated at build time, and the fonts are read once when the module loads.
- **Home page.** It is built from server components with small motion islands, and `initial={false}` means nothing starts hidden, so LCP isn't delayed.
- **Animations.** Loops pause off-screen through IntersectionObserver, and reduced motion is honoured in both JS and CSS.
- **BotID.** It only loads its challenge when a protected request is made.

## 5. Scalability

The site is mostly static and will scale on Vercel's CDN. The limits that remain are in state and in dynamic routes.

- **Per-instance state.** The public API limit, the contact rate limit and the delivery idempotency map (`startedDeliveries`) all live in module-level memory. On serverless:
  - Limits are effectively multiplied by the number of warm instances.
  - The maps never shrink (S8, S9).
  - Idempotency across instances depends on Resend's `Idempotency-Key` alone.

  Move idempotency into the workflow (a deterministic run or hook ID) and rate limiting into the Vercel WAF or `@vercel/firewall`, which the contact routes already use.
- **Content growth.** Reads are synchronous filesystem reads on every dynamic request, with no memoisation (P3). That's fine for 40 posts but grows linearly. Memoise per deployment, or build a JSON content index at build time.
- **AI spend.** A $5 Gateway budget with no auto-refill is the backstop, which is good. Pair it with the kill-switch fix (S3) so the switch actually stops spend.
- **Hosting coupling.** The README says Railway can host the shell, but BotID, Firewall, Blob and Workflow are Vercel-only (S14). Either document Vercel as the only supported host, or put those features behind adapters.

## 6. Accessibility (WCAG 2.2 AA)

### Strengths

- **Page structure.**
  - `lang="en"`, a viewport that doesn't block zoom, and `color-scheme` with `light-dark()`.
  - The theme is applied before first paint.
  - One `<main>` and one `<h1>` per page, labelled navs, `aria-current`, and Markdown `h1` demoted to `h2`.
- **Mobile menu.** It has `aria-expanded`/`aria-controls`, moves focus into the menu, closes on Escape and returns focus afterwards.
- **Accessible names.** Every icon-only control has one, and new-tab links are announced.
- **Reduced motion.** A global CSS kill switch plus `useReducedMotion` in every hook. The contact workflow demo has Pause/Prev/Next controls.
- **Contact composer.** It uses `aria-invalid` + `aria-describedby` + `role="alert"`, with 44 px targets.
- **Embeds.** YouTube is a titled click-to-load facade, and the tweet embed has a blockquote fallback.
- **Contrast.** Core text colours pass AA in both themes: primary text 10.2 : 1 in light and 17 : 1 in dark.
- **Storybook.** It runs axe with `a11y.test: "error"`, and about 180 stories have play functions.

## 7. Architecture & maintainability

### Strengths

- **Domain modules.** `src/lib` holds small, pure, well-tested modules. zod is used at every boundary, and the OpenAPI document is generated from zod.
- **Type safety.** 0 `any`, 0 `@ts-ignore`, 1 production non-null assertion, and 6 `eslint-disable` comments, all for `no-img-element`.
- **Drift tests.** Unit tests catch drift in generated artifacts: the skills copy, the design tokens against `applification.pen`, and markdown parity.
- **Shared helpers.** The public `/api/v1` routes use shared helpers in `public-content-http.ts`.

## 8. Testing

### Strengths

- **Behavioural tests.** Most tests check behaviour. Dependencies are injected (`fetch` is passed into `prepareContact` and `sendContactDelivery`) rather than mocked, and only 2 files use `vi.mock`.
- **Deterministic time.** Tests pass an explicit `now`, call `setSystemTime`, or use workflow `wakeUp`. There are no real network calls and no `.skip` or `.only`.

### Suggested CI (`.github/workflows/ci.yml`)

```yaml
name: ci
on:
  pull_request:
  push:
    branches: [main]
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: oven-sh/setup-bun@v2
        with: { bun-version-file: package.json }
      - uses: actions/setup-node@v4
        with: { node-version: 22 }
      - uses: actions/cache@v4
        with:
          path: ~/.bun/install/cache
          key: bun-${{ runner.os }}-${{ hashFiles('bun.lock') }}
      - run: bun install --frozen-lockfile
      - working-directory: apps/applification
        run: |
          bun run lint
          bunx next typegen && bunx tsc --noEmit
          bun run test -- --coverage
          bun run test:workflow
          bun run skills:sync && git diff --exit-code -- ../../skills

  storybook:
    needs: check
    runs-on: ubuntu-latest
    steps:
      # checkout + setup-bun + setup-node + install (as above)
      - run: bunx playwright install --with-deps chromium
        working-directory: apps/applification
      - run: bunx vitest run --project storybook
        working-directory: apps/applification

  build:
    needs: check
    runs-on: ubuntu-latest
    steps:
      # checkout + setup-bun + setup-node + install (as above)
      - uses: actions/cache@v4
        with:
          path: apps/applification/.next/cache
          key: next-${{ hashFiles('bun.lock') }}-${{ github.sha }}
          restore-keys: next-${{ hashFiles('bun.lock') }}-
      - run: bun run build
```
